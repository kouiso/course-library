# Security model

- This library distributes the free TypeScript survey-response gift and paid products for buyers (currently `redmine-clone`). A paid product is never part of the free gift. Each collection has its own phrase setting: the gift phrase opens only the gift, a product phrase opens only that product, and a product whose phrase setting repeats another collection's digest is closed. A paid product is listed apart from the gift and stays locked for a gift session; its direct course and download routes are refused. A collection ID that is not in the manifest is refused on direct routes even with valid authentication. Collection ID, distribution kind, audience, filenames and immutable prefixes are validated to prevent product/gift manifest mixing.
- The outer HTTP Basic site gate is required in production before any page and stays in place after distribution starts. How buyers receive their product phrase is decided by the operator and is deliberately not written in this public repository.
- Local synthetic previews are allowed only on a loopback origin. For the survey gift, production requires a non-synthetic published release plus explicit `myaspVerified` and `distributionApproved` policy flags. Both are currently false. For a paid product, production requires a non-synthetic published release plus that product's own `distributionApproved` flag (`productPolicy` for `redmine-clone`, currently true). Approvals are held per collection and are never shared. Valid auth does not bypass these release gates; direct GET/HEAD/Range returns unavailable without object metadata. The optional deployment job runs `npm run release:ready` first, which refuses the release when no collection can be distributed or when an approved gift cannot be distributed; a collection that is not approved stays closed in production.
- The shared phrase is not evidence that a particular person answered the survey. There is no MyASP API or per-reader identity check. The intended respondent-only invitation/phrase delivery must be confirmed in MyASP before enabling production. Do not send the phrase to all newsletter readers or reuse product credentials.

- A high-entropy shared phrase (at least 128 bits of randomness) is compared against an operator-provided SHA-256 digest with constant-time digest comparison. This design requires a random phrase; a memorable human password would require a slow password KDF and revised CPU/plan assessment. No phrase, digest, signing key, or PDF password is checked in.
- HMAC-SHA-256 session tokens include purpose, issued/expiry times, and a fresh random nonce. Login always creates a new token. Tokens expire after four hours. Rotating `SESSION_SECRET` revokes all sessions; the phrase and signing secret must be rotated together when access is withdrawn.
- Production uses Secure, HttpOnly, SameSite=Strict, host-only `__Host-` cookies. A separate localhost-only mode is set by the synthetic preview. Production HTTP and placeholder origins are refused.
- Login needs an expiring signed anti-CSRF token bound to an HttpOnly cookie, an exact Origin, and compatible Fetch Metadata. Logout needs the session nonce and exact Origin. Form bodies are bounded to 4 KiB; duplicate fields and cookies are rejected. Redirect destinations are fixed internal paths.
- IP and aggregate rate-limit bindings run before phrase checks. IP keys are hashed and never logged. The thresholds are 5 attempts per IP and 60 overall per 60 seconds **per Cloudflare location**. Native limits are approximate and cannot stop a global distributed attacker by themselves. Random phrase entropy is essential. Shared networks may see temporary rate-limit errors.
- Every material request authenticates before looking up metadata, including HEAD, Range and conditional requests. Only manifest filenames and fixed release prefixes reach R2. Multi-range is rejected; one range is streamed with validated bounds. A zero-byte object is an unfinished upload: GET, HEAD and Range return a no-store 503 preparation page before any attachment, ETag or range metadata is built. R2 metadata cannot override cache or disposition headers.
- Every application response has `private, no-store`, both CDN no-store headers, and `Vary: Cookie`; the code never calls Cache API. Review zone cache rules before activation and verify at the actual public edge. Browser/service-worker/shared CDN overrides outside this project are not covered by local tests.
- CSP permits only same-origin stylesheet and progressive-enhancement script, disallows framing and base changes, and restricts form destinations. No external scripts or analytics.
- `Referrer-Policy: same-origin` keeps external referrers private while preserving the browser's Origin on same-origin form POSTs. Chromium form navigation with `no-referrer` produced `Origin: null` during visual verification and was correctly refused by CSRF protection; the browser test guards the working submission path.
- Missing secrets, invalid origins, missing bindings and exceptions return unavailable responses. Credentials, cookies, request bodies and material keys are never logged by application code. Wrangler observability is disabled; review account-level logs separately before activation.

A shared-phrase service cannot identify individual recipients or prevent authorized readers from copying files. Logout clears that browser cookie; a copied stateless token remains valid until expiry or key rotation. PDF open-password encryption protects unopened distribution copies; it is not DRM. Keep useful copy and print permissions enabled.

No real material, encryption, credential creation, R2 provisioning, or deployment has been performed by the prototype.
